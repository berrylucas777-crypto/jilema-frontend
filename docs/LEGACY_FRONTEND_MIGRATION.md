# 新前端接入旧代码库：迁移与接口批注

更新日期：2026-08-20

## 结论

当前 `index.html` 是经过产品确认的交互与视觉基准，旧 `jidian` 仓库是线上业务、真实接口和真实数据的实现基准。迁移时不应让任一方直接覆盖另一方。

采用的方式是“新 UI + 兼容适配层 + 逐页面替换”：

```text
旧 Flask API
  ↓ 原始字段
integration/legacy-api-adapter.js
  ↓ 稳定页面模型
当前确认版 UI
```

旧接口改字段时，只修改适配层；新 UI 改排版时，不修改后端。这样可以把视觉复刻和接口联调拆成两类独立任务。

## 如何查看真实接口模式

默认链接仍使用稳定 Demo 数据：

```text
http://127.0.0.1:4174/?mainTab=feed
```

增加参数后读取旧系统公开接口：

```text
http://127.0.0.1:4174/?mainTab=feed&apiMode=legacy
```

本地先运行 `npm run dev`。预览服务器会把同源 `/api/*` 转发到旧系统，从而避开浏览器跨域限制；如需切换后端，可通过 `JILEMA_API_TARGET` 指定。登录态继续兼容旧系统的 `localStorage.jidian_session.token`，请求头仍为 `X-Token`。

## 为什么不能直接“一比一复刻”

1. 当前 Demo 把结构、状态和演示数据写在单文件中；旧项目使用 Vue、Pinia、Router 和 Axios。
2. 新页面需要的概念比旧接口更多，例如“学院 → 专业 → 课程 → 老师”，旧数据没有可靠的专业字段。
3. 旧接口按数据库字段返回；新 UI 按用户任务组织内容，两者层级不同。
4. 新页面包含通知、二手、拼车和跑腿等新场景，旧后端并没有完整接口。
5. 视觉复刻、业务状态、路由和接口若在同一次任务里一起修改，AI 很容易用临时数据填空，造成表面相似、实际不可接。

## 降低工作量的开发规则

### 1. 先锁定页面模型

每个正式组件只接收新模型，例如 `ForumPost`、`CourseReview`、`Material`。组件内禁止读取 `comment_count`、`major_hint` 等旧字段。

### 2. 逐页面迁移

建议顺序：

1. 暨了么首页只读信息流。
2. 帖子详情与回复。
3. 选课列表与课程详情。
4. 备考资料列表与下载。
5. 登录、收藏、发布和上传等写操作。
6. 通知与“我的”。

每完成一个页面就让真实用户可用，不等待全站一次性重写。

### 3. 先读后写

第一批只接 `GET` 接口。确认展示字段、空状态和错误状态稳定后，再接发布、评论、点赞、收藏和上传。这样不会因 UI 仍在调整而误写线上数据。

### 4. 缺失信息明确显示

旧数据没有专业归属时显示“专业信息待补”，禁止从课程名猜专业。猜测数据会让面包屑看起来完整，却会破坏选课可信度。

### 5. 用契约和夹具让两个 AI 对齐

每个接口至少保留：

- 一份成功响应样例。
- 空列表样例。
- `401 / 404 / 500` 样例。
- 对应页面模型。
- 映射测试。

后端 AI 只保证旧接口契约或提供新版本；前端 AI 只消费适配后的页面模型。

## 后续正式工程建议

当前适配层用于降低第一轮迁移成本。进入生产 Vue 工程时，应把它拆为：

```text
src/
├── api/                 # 只负责 HTTP、鉴权和错误
├── contracts/           # OpenAPI 生成的旧接口类型
├── adapters/            # 旧接口 → 新页面模型
├── models/              # ForumPost / CourseReview / Material
├── features/            # 按业务页面组织组件和状态
└── mocks/               # 与接口契约一致的本地数据
```

不建议现在引入微前端。暨了么前后端规模仍适合单 Vue 应用，微前端会额外增加路由、共享状态、样式隔离和部署成本。只有在多个独立团队需要分别发布不同业务域时再考虑。

## GitHub 调研依据

- [OpenAPI Generator](https://github.com/OpenAPITools/openapi-generator)：由接口契约生成客户端与类型，适合在第二阶段减少前后端手写字段错误。
- [Pact JS](https://github.com/pact-foundation/pact-js)：消费者驱动契约测试，适合验证“前端真正依赖的响应字段”没有被后端改坏。
- [Mock Service Worker](https://github.com/mswjs/msw)：在网络层复用接口 Mock，适合让前端开发不被后端进度阻塞。
- [Playwright](https://github.com/microsoft/playwright)：可做跨浏览器流程与截图对比，适合锁定确认版页面的关键视觉与交互。
- [single-spa](https://github.com/single-spa/single-spa)：支持逐步迁移和多前端共存，但当前团队规模下不建议立即采用；先用路由级逐页替换更轻。

本次实际采用了其中最轻量的组合：适配层、确定性 Demo、映射测试、路由级逐批迁移。OpenAPI、Pact 与截图基线留到正式 Vue 工程迁移时接入，避免当前 Demo 过早工程化。

## 本次代码批注位置

- `integration/legacy-api-adapter.js`：旧接口兼容与字段翻译的唯一入口。
- `template.html`：只保留“如何把适配数据放入当前 UI”的消费逻辑。
- `build.mjs`：构建时将兼容层内联到 `index.html`，继续保持单文件可分享。
- `integration/legacy-api-adapter.test.mjs`：用旧接口典型字段验证映射没有漂移。
